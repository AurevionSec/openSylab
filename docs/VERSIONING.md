# Version Management — Single Source of Truth

OpenSylab uses two canonical sources for the version number, both of which are changed
in sync during a release bump. All other files reference these sources
automatically — no manual adjustments needed.

---

## Architecture

```
CMakeLists.txt                     frontend/package.json
  project(OpenSylab VERSION 1.1.0)   "version": "1.1.0"
         │                                    │
         ▼ cmake configure_file              ▼ vite define (vite.config.ts)
   include/version.h               import.meta.env.VITE_APP_VERSION
         │                                    │
         ├── src/main.cpp                     └── src/components/Layout/Sidebar.tsx
         ├── src/utils/CliInterface.cpp
         └── test/unit/test_runner.cpp
```

### C++ — `CMakeLists.txt`

```cmake
project(OpenSylab
    VERSION 1.1.0          # ← change HERE for a new release
    DESCRIPTION "..."
    LANGUAGES CXX
)

configure_file(
    "${CMAKE_SOURCE_DIR}/include/version.h.in"
    "${CMAKE_SOURCE_DIR}/include/version.h"
    @ONLY
)
```

During configuration, CMake generates `include/version.h` from the template
`include/version.h.in`. The header defines:

| Macro | Example value |
|-------|-------------|
| `OPENSYLAB_VERSION` | `"1.1.0"` |
| `OPENSYLAB_VERSION_STRING` | `"OpenSylab v1.1.0"` |
| `OPENSYLAB_VERSION_MAJOR` | `0` |
| `OPENSYLAB_VERSION_MINOR` | `7` |
| `OPENSYLAB_VERSION_PATCH` | `0` |

Usage in C++:

```cpp
#include "version.h"

std::cout << OPENSYLAB_VERSION_STRING << "\n";  // "OpenSylab v1.1.0"
```

### Frontend — `package.json`

```json
{
  "name": "frontend",
  "version": "1.1.0"    ← change HERE for a new release
}
```

`vite.config.ts` reads the version at build time and injects it:

```typescript
import pkg from './package.json'

export default defineConfig({
  define: {
    'import.meta.env.VITE_APP_VERSION': JSON.stringify(pkg.version),
  },
})
```

Usage in the frontend:

```tsx
<span>{import.meta.env.VITE_APP_VERSION}</span>  {/* "1.1.0" */}
```

> **Note:** `VITE_APP_VERSION` is a build-time value — it is hardcoded into the
> bundle and does not change at runtime.

## Bumping the version (release process)

```bash
# 1. Update both SSoTs
#    CMakeLists.txt: VERSION 1.0.0 → 1.1.0
#    frontend/package.json: "version": "0.8.0"

# 2. Rebuild C++ (generates version.h)
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel $(nproc)

# 3. Rebuild the frontend
cd frontend && npm run build

# 4. Verify
./build/bin/OpenSylab --api --api-port 9080 --db /tmp/test.db &
grep "0.8.0" frontend/dist/assets/*.js
```

## Files that do NOT need to be adjusted manually

| File | Reason |
|-------|-------|
| `include/version.h` | Generated by CMake — do **not** commit without a rebuild |
| `src/main.cpp` | Uses `OPENSYLAB_VERSION_STRING` |
| `src/utils/CliInterface.cpp` | Uses `OPENSYLAB_VERSION` |
| `test/unit/test_runner.cpp` | Uses `OPENSYLAB_VERSION_STRING` |
| `frontend/src/components/Layout/Sidebar.tsx` | Uses `import.meta.env.VITE_APP_VERSION` |

## Semantic Versioning

OpenSylab follows [Semantic Versioning 2.0.0](https://semver.org):

| Change | Version |
|----------|---------|
| Backward-incompatible API changes, DB schema migration required | `MAJOR` |
| New features, backward-compatible | `MINOR` |
| Bug fixes, security patches | `PATCH` |

Current version: **1.1.0** — stable; from 1.0 the API follows SemVer (breaking changes only in major releases).
